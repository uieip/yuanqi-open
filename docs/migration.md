# 迁移与对比

## 1. 和常见方案对比

| 维度 | 传统自研 | 低代码 SaaS | UIEIP 开源版 |
| --- | --- | --- | --- |
| 起步成本 | 高，需搭框架、权限、流程 | 低，但受平台限制 | 低，解压即用 |
| 数据存放 | 自有 | 多在厂商云上 | 自有服务器 / 自有数据库文件 |
| 定制能力 | 完全自由 | 受组件与插件限制 | 服务端 JavaScript + 组件扩展 |
| 私有化 / 国产化 | 需自建 | 通常不支持或成本高 | 单文件部署，正式版支持国产数据库 |
| 流程 / 权限 / SSO | 需逐个实现 | 部分内置 | 内置 |
| 迁移成本 | — | 锁定风险高 | 模型与数据在自有库中，可导出 |

## 2. 从其他低代码平台迁入

建议按「先模型、再数据、后界面、最后流程」的顺序：

1. **梳理模型**：把原平台的表单/实体拆成表、字段、枚举、外键，在 **数据管理**（`/adp/data.html`）重建。
2. **迁移数据**：按业务表导出 CSV，通过平台导入或直接写入数据库；注意主键 `sid`、外键、日期格式。
3. **重建权限**：先用 `/adp/hr_org.html`、`/adp/hr_post.html`、`/adp/hr_user.html` 对齐组织与人员，再在 `/adp/roles.html` 配角色与操作标识。
4. **重建页面**：优先用内置列表/表单模板，个性化界面再用 YQWIN-Plus 组件搭建。
5. **重建流程**：在 `/adp/wfedit.html` 画流程，配置状态字段回写，历史单据按已完结处理，不强行迁入运行中实例。
6. **对账**：抽样比对数据条数、金额、状态；用接口或报表做交叉验证。

## 3. 开源版 → 正式版

| 项 | 开源版（本包） | 正式版 |
| --- | --- | --- |
| 操作系统 | Windows x64 | Windows / Linux / macOS |
| 数据库 | SQLite | SQLite / PostgreSQL / KingbaseES，持续适配 MySQL、openGauss、GaussDB、OceanBase、TiDB |
| 部署 | 单文件、解压即用 | 服务化、容器化 |
| 支持 | 社区 | 按授权提供 |

迁移步骤（以 SQLite → PostgreSQL 为例）：

1. 在正式版环境中建库建用户，准备与 `db.yqbase.connStr` 对应的连接串。
2. 用平台提供的建表脚本在目标库初始化结构与基础数据。
3. 迁移业务数据：按表导出 SQLite 数据，注意自增/序列、布尔与日期类型差异。
4. 修改 `config.json`：`db.lists`、`db.yqbase.driver`、`db.yqbase.connStr`，文件柜同步改为目标存储。
5. 启动后逐项验证：登录、菜单、列表、表单、流程、文件、SSO。
6. 切换前保留原 SQLite 文件与 `files/` 目录，确认无误后再下线旧环境。

> 多数据库、跨平台与增强能力以正式版实际发布/授权为准。

## 4. 迁移检查清单

- [ ] 表结构、字段类型、枚举值一一对应
- [ ] 主键与外键关系保持，树形/排序字段正确
- [ ] 菜单、角色、操作标识与原来一致
- [ ] 流程状态字段能正确回写
- [ ] 附件与图片可访问（`files/` 或数据库文件）
- [ ] 定时任务、外部接口地址已更新
- [ ] 备份可用，回滚方案明确
