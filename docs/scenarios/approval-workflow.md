# 场景教程：搭建一套审批流程

以「请假申请」为例：业务表 + 审批流 + 状态回写 + 待办处理。

## 1. 建业务模型

进入 **管理后台 → 数据管理**（`/adp/data.html`），新建业务表，例如 `leave_apply`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sid` | 文本 | 主键（平台生成） |
| `apply_user` | 文本 / 人员 | 申请人 |
| `dept` | 文本 / 部门 | 申请部门 |
| `leave_type` | 枚举 | 事假 / 病假 / 年假 |
| `begin_time` / `end_time` | 日期时间 | 起止时间 |
| `days` | 数值 | 请假天数 |
| `reason` | 文本 / 富文本 | 事由 |
| `state` | 文本 | 流程状态（由流程回写） |

建模完成后，平台会自动创建数据表并生成通用增删改查接口。字段的显示形态、宽度、是否只读等在 **字段配置**（`/adp/fields.html`）中调整。

## 2. 设计流程

进入 **管理后台 → 流程管理**（`/adp/wfedit.html`）新建流程，用“点 + 线”的方式连线：

```text
Start ──► Exec（直属上级审批）──► Judge（days > 3 ?）
                                      │ 是                    │ 否
                                      ▼                       ▼
                              Exec（部门负责人审批）          End
                                      │
                                      ▼
                                     End
```

可用节点：

| 节点 | 用途 |
| --- | --- |
| Start | 发起流程 |
| Exec | 执行/审批，可指定人员、岗位、部门+职位、发起人部门+职位，或用代码取人 |
| Judge | 按出线表达式判断分支 |
| Proc | 程序节点，调用接口或发消息 |
| Return | 退回指定状态 |
| End / Cancle | 结束 / 取消 |
| Comment | 画布注释，不参与流转 |

执行节点常用配置：

- 通过方式：单人审批、最小通过人数、最小通过百分比、全部通过
- 允许人员变更、自动审批、代审
- 退回次数统计、全局参数、提交记录

## 3. 绑定业务状态

在流程属性的「接口信息」中配置业务表与状态字段（见设计器右侧属性面板）：

| 配置 | 作用 |
| --- | --- |
| 程序地址 | 流程节点回调的服务端程序 |
| 数据库 / 表 | 业务表，如 `yqbase` / `leave_apply` |
| 状态字段 | 业务表中记录流程状态的字段，如 `state` |
| 状态程序 | 状态取值来源（枚举或程序） |
| 发起状态 / 状态名称 | 提交时的初始状态 |
| 全局参数 | 流程级参数，可在脚本中读取 |

提交后，业务表状态字段由流程版本配置自动回写；运行数据保存在 `wf_info`、`wf_json`、`wf_todo`、`wf_comp`。

## 4. 发起与处理

| 功能 | 路径 |
| --- | --- |
| 我的流程 | `/adp/wf_my.html` |
| 待办 | `/adp/wf_todo.html` |
| 已办 | `/adp/wf_comp.html` |

审批人可在待办中通过、退回或转交；发起人可查看流转轨迹与退回次数。

## 5. 常见问题

- **审批人取不到**：确认「部门 + 职位」等取人规则与实际组织数据一致，或改用代码取人。
- **状态没有回写**：检查流程属性中的数据库、表名、状态字段是否与业务表一致。
- **流程改了但旧单仍走旧逻辑**：流程按版本管理，已发起的实例继续使用其版本配置。
