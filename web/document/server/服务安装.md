# 一、Docker

- 基本命令

```bash
# 查看 Docker 版本
docker version

# 启动 Docker 服务
sudo service start docker

# 停止 Docker 服务
sudo service stop docker

# 重启 Docker 服务
sudo service restart docker

# 查看 Docker 服务状态
sudo service status docker

# 设置 Docker 开机自启
sudo service enable docker

# 禁止 Docker 开机自启
sudo service disable docker

# 查看 Docker 容器
docker ps

# 查看所有容器（包括已停止的）
docker ps -a

# 查看最近创建的容器（默认显示前 5 个）
docker ps -n 5

# 查看 Docker 镜像
docker images

# 启动一个已停止的容器
docker start <容器名或ID>

# 停止一个运行中的容器
docker stop <容器名或ID>

# 重启一个容器
docker restart <容器名或ID>

# 强制停止容器（不推荐，相当于断电）
docker kill <容器名或ID>

# 暂停容器进程
docker pause <容器名或ID>

# 恢复被暂停的容器
docker unpause <容器名或ID>
```

- Docker 移除实例（容器）的方法

```bash
# 移除已停止的容器
docker rm <容器名或ID>

# 强制移除运行中的容器（会先停止再删除）
docker rm -f <容器名或ID>

# 移除容器并删除其关联的匿名卷
docker rm -v <容器名或ID>
```

# 三、Nginx
Nginx是一款轻量级的Web 服务器/反向代理服务器及电子邮件（IMAP/POP3）代理服务器，在BSD-like 协议下发行。其特点是占有内存少，并发能力强，nginx的并发能力在同类型的网页服务器中表现较好，能够支持高达 50,000 个并发连接数的响应。

- 程序下载地址：https://nginx.org/en/download.html
## 1. 在Windows上安装Nginx
- 下载后解压文件
- windows启动Nginx，两种方法：
（1）直接双击nginx.exe，双击后一个黑色的弹窗一闪而过。
（2）打开cmd命令窗口，切换到nginx目录下，输入命令 nginx.exe 或者 start nginx ，回车即可。
检查nginx是否启动成功。
直接在浏览器地址栏输入网址 http://localhost:80 回车，出现以下页面说明启动成功。
也可以在cmd命令窗口输入命令 tasklist /fi “imagename eq nginx.exe” ，出现结果说明启动成功。
- nginx的配置文件是conf目录下的nginx.conf，默认配置的nginx监听的端口为80，如果80端口被占用可以修改为未被占用的端口即可。
- 检查80端口是否被占用的命令是： netstat -ano | findstr 0.0.0.0:80 或 netstat -ano | findstr “80”
重启：nginx -s reload
关闭： nginx -s stop(快速停止nginx)
关闭： nginx -s quit(完整有序的停止nginx)
关闭：使用taskkill taskkill /f /t /im nginx.exe
- 如果网络无法访问，需要将nginx.exe程序注册到windows防火墙的入站规则中
- 以上为手动启动服务，可以使用nssm注册到服务，开机自动启动。
- conf示例

```json
worker_processes  1;

events {
    worker_connections  1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;

    sendfile        on;
    keepalive_timeout  65;
	
	# 将nginx代理的所有请求实体的大小限制为1024m
    client_max_body_size 1024m;

    server {
        listen       80;
        server_name  localhost;

        location / {
            root   html;
            index  index.html index.htm;
        }

        error_page   500 502 503 504  /50x.html;
        location = /50x.html {
            root   html;
        }
    }

    upstream www {
       server 127.0.0.1:8000  weight=1 fail_timeout=5s max_fails=3;
    }

    server {
        listen 80;
  	  server_name www.spring.com spring.com;
  	  location / {
    		proxy_pass http://www;   #指定upstream分组的名称
    		server_name_in_redirect on;
    		port_in_redirect off;
    		charset utf-8;

    		#设置主机头和客户端真实地址，以便服务器获取客户端真实IP
    		proxy_set_header Host $http_host;		#包含客户端真实的域名和端口号
    		proxy_set_header X-Real-IP $remote_addr;	#表示客户端真实的IP
    		proxy_set_header X-Scheme $scheme;      #传递协议
    		proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; #在多层代理时会包含真实客户端及中间每个代理服务器的IP
			
			#nginx配置websocket支持wss
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
            proxy_read_timeout 600s;
   	 }
    }
}
```
## 2. 在Ubuntu上安装 Nginx
1. 更新软件包列表
首先，确保你的系统软件包列表是最新的
```
sudo apt update
```
2. 安装 Nginx
```
sudo apt install nginx
```
3. 启动 Nginx 服务
安装完成后，Nginx 会自动启动。你可以使用以下命令来确认 Nginx 是否正在运行：
```
sudo systemctl status nginx
```
4. 设置 Nginx 开机自启动
为了确保 Nginx 在系统重启后自动启动，你可以启用它的开机自启动功能：
```
sudo systemctl enable nginx
```
5. 配置防火墙（如果启用了 UFW）
如果你使用的是 UFW 防火墙，你需要允许 HTTP 和 HTTPS 流量：
```
sudo ufw allow 'Nginx Full'
```
你可以通过以下命令检查 UFW 的状态：
```
sudo ufw status
```
6. 测试 Nginx
打开浏览器并访问你的服务器的 IP 地址或域名，例如：
```
http://your_server_ip
```
你应该会看到 Nginx 的默认欢迎页面，表示 Nginx 已经成功安装并运行。
7. 管理 Nginx 服务
你可以使用以下命令来管理 Nginx 服务：
停止 Nginx：
```
sudo systemctl stop nginx
```
重启 Nginx：
```
sudo systemctl restart nginx
```
重新加载 Nginx（在不中断服务的情况下重新加载配置）：
```
sudo systemctl reload nginx
```
禁用 Nginx 开机自启动：
```
sudo systemctl disable nginx
```
8. 配置文件位置
Nginx 的配置文件通常位于 /etc/nginx/ 目录下。主要的配置文件是 /etc/nginx/nginx.conf，而站点配置文件通常位于 /etc/nginx/sites-available/ 目录下，并通过符号链接到 /etc/nginx/sites-enabled/ 目录。
9. 卸载 Nginx
如果你需要卸载 Nginx，可以使用以下命令：
```
sudo apt remove nginx nginx-common
```
如果你想彻底删除 Nginx 及其配置文件，可以使用：
```
sudo apt purge nginx nginx-common
```
然后清理不再需要的依赖项：
```
sudo apt autoremove
```

# 四、消息队列服务:NSQ
NSQ是一个基于Go语言编写的开源实时分布式内存消息队列，主要用于大规模处理每天数以亿计的消息，具有高性能和无单点故障的分布式拓扑结构。

[https://nsq.io/](https://nsq.io/ "https://nsq.io/")
## 1. 简介
NSQ 是一个实时分布式消息队列，专为高性能、高可靠性设计。它不依赖外部的存储系统，只管消息的传递和处理。它的设计理念非常简单，就是尽量让每个组件做自己该做的事。NSQ 主要有三个重要组件，我们来一个个看：
- **nsqd**：这是核心组件，负责和客户端通信，处理消息的发布和消费。它提供 TCP (端口 4150) 和 HTTP (端口 4151) 接口。
- **nsqlookupd**：它是个路由器，客户端通过它来发现生产者和话题的存在。一般来说，它会监听端口 4160 (TCP) 和 4161 (HTTP)。
- **nsqadmin**：这是一个管理后台，提供一个浏览器界面，可以查看消息队列的状态，监控各类指标，监听端口 4171。
- **nsqd和nsqlookupd区别**
nsqd和nsqlookupd在NSQ系统中扮演不同的角色，具有不同的功能和运行机制。
nsqd：nsqd是一个守护进程，负责接收、排队和投递消息给客户端。它独立运行，但通常由nsqlookupd实例所在的集群配置。nsqd负责处理具体的消息队列操作，包括接收消息、存储消息、并将消息发送给消费者。
nsqlookupd：nsqlookupd管理NSQ系统的拓扑信息，客户端通过特定的topic查询nsqlookupd来发现nsqd生产者及广播topic和channel信息。它类似于系统的神经中枢，启动后会同时监听两个端口：4160端口用于TCP通信，4161端口用于HTTP通信。
- **运行机制和架构**
nsqd：nsqd会向所有的nsqlookupd上报本地信息，因此nsqlookupd具有最终一致性。nsqd的入口函数位于nsq/apps/nsqlookupd/main.go中，通过第三方svc包进行优雅的后台进程管理。
nsqlookupd：nsqlookupd启动后会同时监听两个端口，4160端口用于TCP通信，4161端口用于HTTP通信。它作为后台服务运行，类似于apache的守护进程模式，确保系统稳定运行。

1. 执行 nsqlookup
nsqlookupd是管理拓扑信息的守护进程。客户端查询nsqlookupd以发现特定主题的nsqd生产者，nsqd节点广播主题和通道信息。
```
nsqlookupd 
```
2. 执行 nsqd
nsqd是接收消息、排队并将消息传递给客户机的守护进程。
```
nsqd --lookupd-tcp-address=127.0.0.1:4160
```
3. 执行 nsqadmin
nsqadmin是一个Web UI，用于实时查看聚合的集群统计信息并执行各种管理任务。
```
nsqadmin --lookupd-http-address=127.0.0.1:4161
```
http://127.0.0.1:4171/
4. 测试
发布一个初始消息
```
curl -d "hello world 1" "http://127.0.0.1:4151/pub?topic=test"
```
## 2. 服务安装
-  1）linux服务安装（ubount）

```
# 创建 nsq 系统用户和组（无登录权限）
sudo groupadd --system nsq
sudo useradd --system --no-create-home -g nsq --shell /bin/false nsq

# 创建 NSQ 二进制文件目录（假设您将二进制文件放在 /etc/nsq/）
sudo mkdir -p /etc/nsq/
sudo chown nsq:nsq /etc/nsq/

# 创建工作目录
sudo mkdir -p /var/lib/nsq
sudo chown nsq:nsq /var/lib/nsq

# 创建日志目录和日志文件
sudo mkdir -p /var/log/nsq
sudo touch /var/log/nsq/nsqlookupd.log
sudo touch /var/log/nsq/nsqlookupd.error.log
sudo chown -R nsq:nsq /var/log/nsq

# 重新加载 systemd 和 logrotate
sudo systemctl daemon-reload
sudo systemctl restart logrotate
```

/etc/systemd/system/nsqlookupd.service

```
[Unit]
Description=NSQLookupd Service
After=network.target

[Service]
Type=simple
User=nsq
Group=nsq
ExecStart=/etc/nsq/nsqlookupd
WorkingDirectory=/var/lib/nsq
Restart=always
RestartSec=5
StandardOutput=file:/var/log/nsq/nsqlookupd.log
StandardError=file:/var/log/nsq/nsqlookupd.error.log

[Install]
WantedBy=multi-user.target
```
/etc/systemd/system/nsqd.service
```
[Unit]
Description=NSQ Daemon
After=network.target nsqlookupd.service

[Service]
Type=simple
User=nsq
Group=nsq
ExecStart=/etc/nsq/nsqd \
    --lookupd-tcp-address=127.0.0.1:4160 \
    --tcp-address=0.0.0.0:4150 \
    --http-address=0.0.0.0:4151

WorkingDirectory=/var/lib/nsq
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
启用并启动服务、查看状态
```
sudo systemctl daemon-reload
sudo systemctl enable nsqlookupd nsqd
sudo systemctl start nsqlookupd nsqd
sudo systemctl status nsqlookupd nsqd
```

```batch
 @echo off

    echo 请修改脚本中的 NSQ_DIR 变量为正确的路径

    exit /b 1

    echo [错误] 找不到文件: %NSQ_DIR%\nsqlookupd.exe
    pause
    exit /b 1
)

if not exist "%NSQ_DIR%\nsqd.exe" (
    echo [错误] 找不到文件: %NSQ_DIR%\nsqd.exe
    pause
    exit /b 1
)

echo [成功] NSQ文件验证通过
echo.

:: 设置NSQd和NSQLookupd的配置参数
set NSQD_CONFIG=--broadcast-address=127.0.0.1 --lookupd-tcp-address=127.0.0.1:4160
set NSQLOOKUPD_CONFIG=

:: 显示将要执行的命令（用于调试）
echo ========================================
echo 将要注册的服务配置
echo ========================================
echo nsqlookupd 路径: "%NSQ_DIR%\nsqlookupd.exe" %NSQLOOKUPD_CONFIG%
echo nsqd 路径: "%NSQ_DIR%\nsqd.exe" %NSQD_CONFIG%
echo.

:: 删除可能已存在的旧服务（避免冲突）

echo ========================================

if %errorlevel% equ 0 (
    echo 发现已存在的 nsqlookupd 服务，正在删除...
    sc stop nsqlookupd >nul 2>&1
    sc delete nsqlookupd >nul 2>&1
    timeout /t 1 /nobreak >nul
)

sc query nsqd >nul 2>&1
if %errorlevel% equ 0 (
    echo 发现已存在的 nsqd 服务，正在删除...
    sc stop nsqd >nul 2>&1
    sc delete nsqd >nul 2>&1
    timeout /t 1 /nobreak >nul
)
echo.

:: 注册为服务 - 方法1（推荐）
echo ========================================
echo 正在注册 NSQ 服务...
echo ========================================

:: 使用完整路径并正确转义引号
sc create nsqlookupd binPath= "\"%NSQ_DIR%\nsqlookupd.exe\" %NSQLOOKUPD_CONFIG%" DisplayName= "Nsqlookupd Service" start= auto
if %errorlevel% equ 0 (
    echo [成功] nsqlookupd 服务注册成功
) else (
    echo [失败] nsqlookupd 服务注册失败，错误代码: %errorlevel%
)

sc create nsqd binPath= "\"%NSQ_DIR%\nsqd.exe\" %NSQD_CONFIG%" DisplayName= "Nsqd Service" start= auto
if %errorlevel% equ 0 (
    echo [成功] nsqd 服务注册成功
) else (
    echo [失败] nsqd 服务注册失败，错误代码: %errorlevel%
)

:: 等待服务注册完成
timeout /t 2 /nobreak >nul

:: 验证服务注册是否成功
echo.
echo ========================================
echo 验证服务注册
echo ========================================
sc qc nsqlookupd | find "BINARY_PATH_NAME"
sc qc nsqd | find "BINARY_PATH_NAME"

:: 启动服务
echo.
echo ========================================
echo 正在启动 NSQ 服务...
echo ========================================

sc start nsqlookupd
if %errorlevel% equ 0 (
    echo [成功] nsqlookupd 服务启动成功
) else (
    echo [失败] nsqlookupd 服务启动失败
    echo 提示：请检查上面的 BINARY_PATH_NAME 是否正确
)

sc start nsqd
if %errorlevel% equ 0 (
    echo [成功] nsqd 服务启动成功
) else (
    echo [失败] nsqd 服务启动失败
    echo 提示：请检查上面的 BINARY_PATH_NAME 是否正确
)

:: 检查服务状态
echo.
echo ========================================
echo 服务状态检查
echo ========================================

sc query nsqd | find "STATE"

echo.
```

## 4. Topic和Channel
在NSQ中，Topic和Channel是两个核心概念，它们共同构成了 NSQ 的消息分发机制。理解它们的作用和关系对于设计和实现基于 NSQ 的消息系统非常重要。
- 1)Topic（主题）
    - Topic 是消息的逻辑分类，生产者将消息发布到特定的 Topic。
    - 每个 Topic 是独立的，消息只会发送到订阅了该 Topic 的消费者。
    - Topic 是消息的第一级分类，通常用于区分不同类型的消息。
    - 举例：
        - 如果你有一个日志系统，可以定义多个 Topic，比如：
        - logs.error（错误日志）
        - logs.info（信息日志）
        - logs.debug（调试日志）
        - 生产者将消息发布到对应的 Topic，消费者根据需要订阅特定的 Topic。

- 2)Channel（通道）
    - Channel 是 Topic 的子分类，用于实现消息的分组消费。
    - 每个 Topic 可以有多个 Channel，每个 Channel 会独立接收 Topic 中的所有消息。
    - Channel 的主要作用是支持多组消费者对同一 Topic 的消息进行独立消费。
    - 举例：
        - 假设有一个 Topic 叫 orders，你可以为它创建多个 Channel：
        - orders.email：用于发送订单确认邮件。
        - orders.notification：用于发送订单通知。
        - orders.analytics：用于订单数据分析。
        - 每个 Channel 会独立接收 orders Topic 中的所有消息，但不同的消费者组可以独立处理这些消息。

- 3)Topic 和 Channel 的关系
    - 一对多关系：一个 Topic 可以有多个 Channel。
    - 消息分发机制：
        - 当生产者发布一条消息到 Topic 时，NSQ 会将这条消息复制到该 Topic 下的所有 Channel。
        - 每个 Channel 会维护自己的消息队列，确保每个消费者组可以独立消费消息。
    - 消费者订阅：
        - 消费者通过订阅某个 Topic 的 Channel 来接收消息。
        - 同一个 Channel 可以有多个消费者，NSQ 会自动将消息分发给这些消费者（负载均衡）。

- 4)Topic 和 Channel 的工作流程
    - 生产者发布消息：
        - 生产者将消息发布到指定的 Topic。
        - 例如：发布一条消息到 orders Topic。
    - 消息复制到 Channel：
        - NSQ 会将消息复制到 orders Topic 下的所有 Channel。
        - 例如：orders.email、orders.notification、orders.analytics 都会收到这条消息。
    - 消费者消费消息：
        - 每个 Channel 的消费者独立消费消息。
        - 例如：
orders.email Channel 的消费者处理邮件发送。
orders.notification Channel 的消费者处理通知发送。

- 5)Topic 和 Channel 的设计建议
    - Topic 的设计：
        - 根据消息的类型或业务逻辑划分 Topic。
        - 例如：user.actions、payment.events、system.logs。
    - Channel 的设计：
        - 根据消费者的职责划分 Channel。
        - 例如：
            - 对于 payment.events Topic，可以创建以下 Channel：
                - payment.email：发送支付确认邮件。
                - payment.notification：发送支付通知。
                - payment.analytics：记录支付数据。
    - 避免过度设计：
        - 不要为每个消费者都创建一个 Channel，只有在需要独立消费时才创建 Channel。
        - 如果多个消费者可以共享同一个 Channel，NSQ 会自动实现负载均衡。

- 6)Topic 和 Channel 的实际应用场景
    - 日志收集：
        - Topic：logs
        - Channel：
            - logs.storage：存储日志到数据库。
            - logs.monitoring：实时监控日志。
        - logs.alert：触发告警。
    - 订单处理：
        - Topic：orders
        - Channel：
            - orders.email：发送订单确认邮件。
            - orders.notification：发送订单通知。
            - orders.analytics：分析订单数据。
    - 消息广播：
        - Topic：broadcast
        - Channel：
            - broadcast.app1：应用 1 接收广播消息。
            - broadcast.app2：应用 2 接收广播消息。

- 7)总结
    - Topic 是消息的第一级分类，用于区分不同类型的消息。
    - Channel 是 Topic 的子分类，用于支持多组消费者独立消费同一 Topic 的消息。
    - Topic 和 Channel 的设计需要根据业务需求合理划分，避免过度设计。
    - NSQ 的消息分发机制基于 Topic 和 Channel，能够很好地支持分布式系统中的消息传递需求。
    - 通过合理使用 Topic 和 Channel，可以构建高效、灵活的消息系统，满足不同场景下的需求。

## 4. Linux上同时使用FRP和Nginx
在Linux上同时使用FRP和Nginx并共享80和443端口是可行的，但需要合理配置，避免端口冲突。
方案：FRP和Nginx分别监听不同的端口
- 让FRP监听非标准端口（如8080和4430），然后通过Nginx反向代理到FRP。
- Nginx继续监听80和443，并将流量转发到FRP的非标准端口。

**配置步骤：**

1. 修改FRP配置文件：
编辑FRP的配置文件（如frps.ini），将HTTP和HTTPS端口改为非标准端口：

```
[common]
bind_port = 7000
vhost_http_port = 8000  #修改HTTP端口为8000
vhost_https_port = 4430 #修改HTTPS端口为4430
```

2. 配置Nginx反向代理：
编辑Nginx的配置文件（如 /etc/nginx/sites-available/default），添加反向代理规则：

```
server {
    listen 80;
    server_name your_domain.com;

    location / {
        proxy_pass http://127.0.0.1:8000;  #转发到FRP的HTTP端口
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

server {
    listen 443 ssl;
    server_name your_domain.com;

    ssl_certificate /path/to/your/certificate.crt;
    ssl_certificate_key /path/to/your/private.key;

    location / {
        proxy_pass https://127.0.0.1:4430;  #转发到FRP的HTTPS端口
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

3. 重启服务：
重启 FRP 和 Nginx 以应用配置：

```
sudo systemctl restart frps
sudo systemctl restart nginx
```
