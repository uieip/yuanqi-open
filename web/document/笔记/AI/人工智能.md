# AI技术概念提纲
## 一、大模型基础
1. LLM（大模型）
   - 定义：大型语言模型的简称，是处理自然语言等任务的核心AI系统。
2. Token（令牌）
   - 定义：大模型处理数据的最基本单元，文本会被拆分为Token进行处理。
3. Context（上下文）
   - 定义：大模型每次处理任务时接收到的信息总和，包含指令、历史对话、背景信息等。
4. Context Window（上下文窗口）
   - 定义：大模型的Context最多能够存储的Token量，决定了模型能“记住”和处理的信息长度上限。
5. Prompt（提示词）
   - 定义：用户或系统当前给大模型下达的具体指令或问题。
   - 细分：它分为User Prompt（用户提示词）。
## 二、大模型扩展与工具
1. Tool（工具）
   - 定义：大模型用来感知和影响外部环境的函数，例如调用API、查询数据库等。
2. MCP
   - 定义：统一了工具接入格式的标准协议，简化了工具与大模型的集成。

## 三、智能体（Agent）与技能
1. Agent（智能体）
   - 定义：能自主规划和调用工具、直至解决用户问题的程序，具备自主决策和执行能力。
   Agent 代表一个独立的、可执行的智能任务单元，能够自主学习，适应与作出决策，主要功能包含：
	- 推理：Agent 可以分析数据、识别模式、使用逻辑和可用信息来得出结论、进行推断及解决问题。
	- 行动：Agent 根据决策、计划或外部输入采取行动或执行任务来实现目标。
	- 观察：Agent 自主收集相关的信息（例如计算机视觉、自然语言处理或传感器数据分析）来了解上下文，为做出明智的决策打下基础。
	- 规划：Agent 可以确定必要的步骤、评估潜在行动，并根据可用信息和预期结果选择最佳行动方案。
	- 协作：Agent 能够在复杂且动态的环境中，与他人（无论是人类还是其他 AI 智能体）进行有效协作。
2. Agent Skill（智能体技能）
   - 定义：给Agent看的说明文档。
   - 作用：主要用来规定做事的步骤和规则，指导Agent完成任务。

### RAG（检索增强生成）
RAG 的核心思想是在LLM生成回复之前，先去外部数据源中查找相关信息，然后将这些信息作为额外上下文提供给LLM，引导其生成更准确的回答。 
RAG 工作流程如下：
1. **数据准备（索引）**
    - **收集和处理外部数据（提前搜集）：** 将各种形式的外部数据（如文档、数据库、网页、API等）收集起来。这些数据可以是企业的内部知识库，也可以是互联网上的公开信息。
    - **切分和嵌入（Transformer）：** 将这些数据切分成小块（称为“chunk”），并使用嵌入模型将每个小块转换为高维度的数字向量（称为“嵌入”）。这些嵌入能够捕捉文本的语义信息。
    - **存储到向量数据库（Embedding&indexer）：** 将这些向量存储在专门的**向量数据库**中，以便后续进行高效的相似性搜索。
2. **检索（Reteriever）**
    - **用户查询：** 当用户提出问题或输入查询时，RAG系统会首先将这个查询也转换为一个向量。
    - **相似性搜索：** 然后，系统会在向量数据库中进行相似性搜索，找到与用户查询最相关的文档块（或片段）。这个过程就像在海量信息中找到最相关的“证据”。
3. **增强生成**
    - **构建增强提示：** 将用户原始的查询和从向量数据库中检索到的相关信息（作为上下文）一起发送给大型语言模型。
    - **LLM 生成回答：** LLM在接收到这个“增强”后的提示后，会根据其自身的训练知识和提供的外部上下文来生成最终的回答。这样，LLM不再仅仅依赖于其训练时的数据，而是有了“实时”的参考资料。


Eino 是什么？
Eino 是一个 Go 语言实现的 AI 应用开发框架（Agent Development Kit），旨在帮助开发者快速构建可扩展、可维护的 AI 应用。
Eino 解决什么问题？
- 模型抽象：统一不同 LLM 提供商的接口（OpenAI、Ark、Claude 等），切换模型无需修改业务代码
- 能力组合：通过 Component 接口实现可替换、可组合的能力单元（对话、工具、检索等）
- 编排框架：提供 Agent、Graph、Chain 等编排抽象，支持复杂的多步骤 AI 工作流
- 运行时支持：内置流式输出、中断与恢复、状态管理、Callback 可观测性等能力

Eino 的主要仓库：
- eino（本仓库）：核心库，定义接口、编排抽象和 ADK
- eino-ext：扩展库，提供各类 Component 的具体实现（OpenAI、Ark、Milvus 等）
- eino-examples：示例代码库，包含本 quickstart 系列



使用 Golang 作为底层开发平台，实现AI 辅助功能（自然语言填单、合规校验、问答、NL2SQL、智能审批建议等），需要完成以下工作。这些工作按照基础设施 → 公共组件 → 业务功能分层，并充分考虑 Go 语言的特点（高并发、强类型、生态偏向 API 调用）。

# 一、基础准备工作（所有功能共用）
## 1.1 大模型接入层（核心）
通过 HTTP/gRPC 调用大模型服务。大模型服务可以是：
* 第三方 API（OpenAI / 国内阿里、智谱、DeepSeek 等）
* 自建私有化模型服务（如 vLLM 部署 Qwen，暴露 OpenAI 兼容接口）

工作项：
* 封装统一的 LLM Client（支持重试、超时、熔断、鉴权、多模型切换）
* 使用 go-openai 库（适配 OpenAI 协议）
* 支持流式/非流式响应，结构化输出强制使用 response_format 或 function calling
* 实现降级：API 不可用时返回默认行为（如跳过 AI，只做规则校验）

代码示例思路：

```go
type LLMClient interface {
    ChatCompletion(ctx context.Context, prompt string, schema interface{}) (string, error)
    // 支持结构化输出
    Structured(ctx context.Context, prompt string, outputStruct any) error
}
```

## 1.2 安全与审计
* 所有发送给大模型的数据必须脱敏（手机号、身份证、姓名用占位符替换）
* 记录每次 AI 调用的请求/响应日志（用于调优和纠纷回溯），但注意不要记录敏感原文
* 设置超时（如 5s）和单次调用 token 上限

## 1.3 成本控制与缓存
* 设计缓存层（Redis）：相同输入（结构化后的请求 key）在 TTL 内复用结果
* 对于复杂但可重复的合规校验（如请假单 + 管理办法版本号作为 key），缓存一小时

# 二、各功能模块的专项工作
## 2.1 自然语言填单（解析描述 → 表单字段）
工作清单：
定义字段映射表：Go 结构体 + JSON tag，例如：

```go
type LeaveForm struct {
    StartDate string `json:"start_date" format:"date" description:"开始日期"`
    EndDate   string `json:"end_date"`
    LeaveType string `json:"leave_type" enum:"事假,病假,年假"`
    Days      int    `json:"days"`
    Reason    string `json:"reason"`
}
```
设计 Prompt 模板（Go 中用 text/template 渲染）：

```go
const parsePrompt = `你是表单提取助手，从用户输入中提取JSON。
输出格式必须严格符合以下Go结构体：
{{.SchemaDesc}}
用户输入：{{.Input}}
只输出JSON，不要解释。
```

实现解析函数：
* 调用 LLM 获取 JSON 字符串
* 用 json.Unmarshal 填充结构体
* 校验必填字段，缺失则返回错误提示（如“未识别到开始日期”）
* 前端集成：提供 HTTP 接口 POST /v1/ai/parse-leave，返回填充后的表单初始数据。

## 2.2 智能合规校验（提交前）
工作清单：

- 规则引擎分层：
	* 硬规则：Go 代码直接实现（例如 if form.Days > 3 && form.LeaveType=="事假"），性能高且确定性。
	* 软规则（AI 辅助）：仅当硬规则通过且涉及复杂管理办法条款时，再调用 LLM。
	* 管理办法知识切片：将《请假管理办法》拆分成短段落，存入向量数据库（如 pgvector 或 Qdrant Go client）。提交时检索相关条款，连同表单一起发给 LLM。

- 合规判断接口：

```go
type ComplianceRequest struct {
    FormData   interface{} `json:"form_data"`
    Rules      []string    `json:"rules"`      // 检索到的条款
    UserRole   string      `json:"user_role"`  // 普通员工/经理
}
type ComplianceResponse struct {
    Pass   bool     `json:"pass"`
    Reason string   `json:"reason"`
    Level  string   `json:"level"` // error, warning
}
```
- 降级策略：若 LLM 超时或返回格式错误，只展示硬规则的校验结果，不阻塞提交。

## 2.3 文档/制度问答助手
技术选型（Go 生态）：
- 向量数据库：pgvector（如果你已用 PostgreSQL）或 Milvus（有 Go SDK）
- 文本嵌入：调用外部嵌入 API（如 text-embedding-3-small）或本地运行 m3e（通过 Python sidecar）

- 工作清单：
	* 离线索引流程：
	* 读取所有制度 PDF/Word → 用 Go 调用 unioffice 提取文本
	* 切块（每 500 token 重叠 50）
	* 计算 embedding → 存入向量库，记录元数据（文档名、章节）
- 在线问答流程：
	* 用户问题 → 计算 embedding → 相似性检索（Top-K）
	* 将检索片段 + 问题拼成 prompt → 调用 LLM 生成答案
	* 返回答案时附带引用来源
	* 提供接口：POST /v1/ai/chat，支持流式输出（SSE 或 WebSocket）

## 2.4 自然语言查询数据（NL2SQL）
高风险功能，需严格安全控制。

- 工作清单：
数据库元数据描述：维护表结构、字段含义、业务术语表的 YAML，供 LLM 理解。
Prompt 设计：

```go
你是一名SQL专家，根据用户问题生成只读SELECT语句。
数据库schema: {{.Schema}}
用户问题: {{.Question
```

- 要求: 
	- 只输出SQL，不要解释
	- 禁止使用DELETE, UPDATE, DROP
	- 限制最多返回100行
	- 如果问题无法回答，输出 "UNSUPPORTED"

- 安全执行：
	* 用 sqlparser（Go）解析生成的 SQL，检查是否为 SELECT 且不包含危险关键字
	* 使用只读数据库连接（GRANT SELECT 单独用户）
	* 设置查询超时（如 3s）和行数限制
	* 结果包装：将查询结果转换为 JSON 或前端表格格式。

## 2.5 智能审批建议
- 工作清单：
	* 特征提取：构建审批样例的特征向量（申请类型、金额/天数、申请人历史批准率、部门预算等）。Go 中定义特征结构体。
	* 预置提示词 + 历史示例：
	* 从数据库取出该审批人最近 20 条审批记录（通过/驳回及理由）
	* 将当前申请单 + 历史记录形成 few-shot prompt
	* 要求 LLM 输出“建议：通过/驳回，置信度分数，理由”

结果展示：在审批界面显示“AI 建议：驳回（87% 置信度），理由：该员工上月已请事假2天，再次申请超过部门限额”。

## 2.6 重复申请检测
- 工作清单：
	* 文本向量化：将表单中的关键字段（请假原因、报销明细摘要）拼接成字符串，计算 embedding。
	* 向量检索：查询该用户近 30 天的申请，计算余弦相似度，阈值 > 0.85 则判定为重复。

接口：在保存申请前调用，返回相似申请列表及链接。

# 六、特别提醒（Go 环境下的坑）
* 大模型响应不稳定：Go 的强类型需要严格处理 json.Unmarshal 失败，必须有降级逻辑（返回原始文本让用户手动修改）。
* 性能：向量检索和 embedding 计算推荐放在独立服务（Python）中，Go 通过 gRPC 调用，避免阻塞 Go 的 goroutine 调度。
* 并发安全：LLM 客户端内部可能并发调用，注意 http.Client 是并发安全的，但 token bucket 限流需要加锁或使用 golang.org/x/time/rate。
