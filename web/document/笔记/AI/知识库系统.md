# 企业级独立部署知识库AI系统

说明：本方案面向企业级独立部署场景，无需考虑多租户隔离，数据规模为中等量级（百万级文档以内），聚焦于系统稳定性、可维护性、私有化部署能力。

## 一、需求定位

需求维度 具体要求  
部署模式 企业内网独立部署（私有化），数据不出企业  
用户规模 企业内部用户，无需多租户隔离  
数据规模 中等量级（文档数 < 100万，知识库总大小 < 100GB）  
核心能力 网站内容检索 + 知识库问答 + 文档管理  
系统要求 高可用、可扩展、易维护、符合企业安全规范  
技术选型 基于Go语言技术栈，使用Eino框架

## 二、总体架构

采用分层单体 + 可扩展服务架构（非多租户场景，无需复杂隔离）：

```
┌─────────────────────────────────────────────────────────────┐
│                         接入层                               │
│        企业门户 / 内部系统 / API客户端 / 管理后台                │
├─────────────────────────────────────────────────────────────┤
│                        API网关层                             │
│               Hertz HTTP / SSE / WebSocket                  │
│                （鉴权 / 限流 / 日志 / 路由）                   │
├─────────────────────────────────────────────────────────────┤
│                      Eino编排层（核心）                       │
│     意图识别 → Graph路由 → RAG检索 → 安全审核 → 流式输出         │
├─────────────────────────────────────────────────────────────┤
│                        领域服务层                             │
│    知识库服务 / 网站采集服务 / 文档管理 / 会话管理                 │
├─────────────────────────────────────────────────────────────┤
│                        数据存储层                             │
│       向量数据库 │ 业务元数据数据库 │ 缓存/会话数据库 │ 文件存储    │
└─────────────────────────────────────────────────────────────┘
```

架构决策：

· 非微服务：中等规模下单体应用 + 后台Worker分离即可满足需求  
· 数据层独立：按存储类型拆分，便于独立扩展  
· 异步解耦：耗时任务（文档采集/批量导入）通过消息队列异步处理

## 三、核心功能模块与技术组件

### 3.1 文档处理与知识库构建


| 功能      | 技术组件                                 | 说明                         |

| 向量化     | Eino Embedding组件 + Embedding模型       | 支持bge-m3/text-embedding-3等 |
| 向量存储    | Milvus 或 Elasticsearch 8.x           | 百万级数据量两者均可                 |
| 业务元数据存储 | PostgreSQL                           | 文档来源、时间戳、分类等               |
| 文件存储    | MinIO / 本地文件系统                       | 原始文件存档（MinIO文件存储层，go语言实现）  |
| 增量更新    | 定时任务 + Webhook触发                     | 支持知识库热更新                   |


### 3.2 检索模块（RAG核心）


| 功能            | 技术组件                         | 说明               |
| ------------- | ---------------------------- | ---------------- |
| 查询改写          | 自研（可选）                       | 口语化转检索友好表达       |
| 向量语义检索        | Milvus KNN / ES dense_vector | TopK召回，默认10-20条  |
| 关键词检索（BM25）   | Elasticsearch                | 精确匹配，与向量检索互补     |
| 混合检索          | RRF融合算法                      | 向量结果与关键词结果融合排序   |
| 标量预过滤         | 表达式引擎                        | 按文档类型/时间范围预筛选    |
| 结果重排序（Rerank） | Cross-Encoder模型              | 可选，提升Top5准确率     |
| 多级缓存          | L1本地（Ristretto）+ L2 Redis    | 高频Query缓存，TTL可配置 |
| 引用来源标注        | 元数据追溯                        | 返回文档链接/来源名称      |

| 功能         | 技术组件                      | 说明             |

| 多轮对话状态管理   | Eino Session + Redis      | 跨轮次上下文保持       |
| 流式输出       | Hertz + Eino Streaming    | SSE推送          |
| 中间件        | 重试/日志/限流/熔断               | 增强鲁棒性          |
| 安全审核       | 敏感词过滤 + 输出审核              | 可选，防止越狱/敏感内容   |


Graph流程示意：

```
用户输入 → 安全审核
    ├─ [通过] → 意图识别 → 路由决策
    │   ├─ 知识问答：查询改写 → 混合检索 → Rerank → 上下文拼接 → LLM生成 → 输出审核 → SSE返回

    └─ [拦截] → 返回安全提示
```

## 分块策略
- 五大经典分块策略

| 策略名称 | 核心思想 | 优点 | 缺点 | 适用场景 |
| ---------- | --------- | ---- | ---- | -------- |
| 固定大小分块 | 按字符或Token数量切分 | 实现简单、速度快 | 易易破坏语义，导致句子或词语被截断 | 结构简单、格式统一的文档（如日志） |
| 递归分块 | 按上述分隔符优先级列表进行递归切割 | 尽可能保留高级语义结构，自适应性强 |  实现稍复杂，性能开销略高于纯固定分块 | 通用性最强，可作为绝大多数场景的默认起点。|
| 语义分块 | 计算相邻句子的向量余弦相似度，在主题变化处分块 | 块内语义连贯性高，能显著提升检索质量 | 计算成本高（需调用嵌入模型），速度慢 | 对检索质量要求极高的场景，如处理主题分散的长文、论文 |
| 基于文档结构 | 利用Markdown标题、PDF页码等元数据识别边界 | 完美贴合文档逻辑结构，信息组织性强 | 依赖高质量的文档解析和结构识别，通用性较弱 | 格式标准的专业文档，如法律合同、学术论文 |
| 句子级分块 | 以自然句子的边界进行切分 | 最大程度保持单句语义完整 | 单个句子可能过短、缺乏上下文，不适用于标点使用灵活的语言 | 对实时性要求高或句子本身信息密度大的场景（如FAQ处理） | 

总的来说，从主流的通用方案起步，选择1024维的向量，采用递归分块策略，设置块大小为512 Token，重叠50 Token。

### 分块策略
- 预处理：给文档“洗个澡”
文本规范化的目标是在不丢失重要边界的前提下，清除随机噪声。建议按以下优先级处理：
   1. 统一“有效”换行，消除“无效”换行
   很多文档里的单换行只是排版自动折行，并非语义段落。
   - **合并多余空行**：将3个及以上连续换行符（可能混有空格）统一压缩为两个换行符（\n\n），即保留最大段落间距。
   - **清除软换行**：将单个出现的换行符替换为空格。这样原本被截断的句子会重新合并，而段落之间的双换行得以保留。
   2. 压缩空格与制表符
   - **英文/中英混排**：将制表符和多个连续空格压缩为1个空格，保证单词间分隔。
   - **纯中文**：中文间空格通常无意义，可直接移除所有空格（但中英数字交界处建议保留1个空格，便于分词模型识别）。

   经过这一步，你的文档会变成：段落内部只有正常空格、句子自然连接；段落之间用双换行清晰分隔。

- 调整递归分块的“优先级列表”
原始分隔符列表通常包含 \n\n、\n、句号、逗号等。由于预处理后，段落内部已无单换行，你可以将递归分隔符简化为：
```text
[“\n\n”, “。”, “.”, “！”, “？”, “；”, “,”, “，”, “ ”, “”]
```
   - 最优先用 \n\n（自然段落）切分。
   - 如果段落仍太长，才会降级到句子标点（如句号、问号），最后才是空格和字符。
   - 这样既能保持语义完整，又能避免误在无效换行处切断。
